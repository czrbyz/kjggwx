01

总览与设计语言

OVERVIEW

ternus 软件商城以「空间光感」为核心设计语言：界面通透、轻盈、有空气感，元素像悬浮在光场之中。上架产品若直接使用浏览器默认样式，会与商城视觉割裂。适配不是可选项，而是上架审核的基本要求。本章给出设计语言的完整定义、适配收益与整体流程，帮助你在动手前建立全局认知。

视觉一致

统一玻璃质感、渐变光效与圆角语言，让产品像商城原生模块，而非外挂网页。

交互一致

hover 光影、动态跟随、卡片上浮等反馈节奏与商城一致，操作手感顺滑自然。

性能与兼容

兼顾首屏性能与移动端体验，并保证 Chrome / Safari / Edge / Firefox 等主流浏览器表现一致。

1.1 什么是「空间光感」

空间光感（Spatial Glow）是一套把「光」当作界面材质的视觉体系：背景是有深度的光场，卡片是悬浮其中的玻璃实体，反馈是光在表面的流动。它区别于扁平设计的「贴纸感」和拟物设计的「塑料感」，核心特征包括：

  • 透光性：元素半透明，背景光可穿透，形成前后空间层次；
  • 折射性：玻璃边缘对背景产生透镜弯曲（SVG 位移滤镜实现真折射）；
  • 反射性：玻璃切面有 1px 白色描边模拟反光，但禁止大面积 CSS 假高光；
  • 动态性：光斑、倾斜、辉光跟随用户操作实时变化；
  • 克制性：所有效果服务信息层级，动画时长 0.25-0.35s，位移 3-6px，不喧宾夺主。

02

空间光感

SPATIAL GLOW

空间光感由四个子规范构成：粒子细化、Liquid Glass 层次、高斯背景玻璃模糊、自然位置变化。四者叠加，界面才具备「空间深度」——元素不再是平贴的纸片，而是悬浮在光中的实体。本章给出每个子规范的设计原理、参数表与可直接复用的代码。

2.1 粒子细化 Particle Refinement

在页面背景加入细颗粒粒子或低对比噪点，让空气可见、让光有介质。粒子应细小、低速、低饱和，只存在于背景层，绝不干扰前景阅读。本页面背景即为此规范的在线演示。

原理：人眼对「静止空白」不敏感，但对「缓慢漂移的微小亮点」极其敏感。粒子层用极低成本让整个页面产生「活着的空气」，是空间光感性价比最高的背景层。

参数推荐值说明
粒子数量30-80 个移动端建议 ≤40，低端机可降至 0（纯静态噪点）
粒子半径0.4-2.0px超过 2px 会像灰尘，破坏精致感
运动速度±0.1-0.3 px/帧肉眼可见但不可追视的漂移速度
颜色rgba(0-90, 122-200, 255, 0.2-0.4)蓝色系低饱和，禁用高亮纯白
透明度整层 0.5-0.65叠加在背景上，不得遮挡文字
最小粒子实现（Canvas）javascript
const cv = document.getElementById('bg');
const ctx = cv.getContext('2d');
const N = 46, dots = [];
for (let i = 0; i < N; i++) {
  dots.push({ x: Math.random()*innerWidth, y: Math.random()*innerHeight,
              r: Math.random()*1.6 + 0.4,
              vx: (Math.random()-.5)*0.25, vy: (Math.random()-.5)*0.25 });
}
function tick() {
  ctx.clearRect(0, 0, cv.width, cv.height);
  for (const d of dots) {
    d.x += d.vx; d.y += d.vy;
    if (d.x < 0 || d.x > innerWidth) d.vx *= -1;
    if (d.y < 0 || d.y > innerHeight) d.vy *= -1;
    ctx.beginPath(); ctx.arc(d.x, d.y, d.r, 0, 7);
    ctx.fillStyle = 'rgba(0,122,255,0.30)'; ctx.fill();
  }
  requestAnimationFrame(tick);
}
tick();
生产级要点：DPR 适配 + 节流 + 降级javascript
// 1) 高 DPR 屏幕按 devicePixelRatio 缩放，避免粒子发虚
cv.width = innerWidth * (window.devicePixelRatio || 1);
cv.height = innerHeight * (window.devicePixelRatio || 1);
ctx.scale(devicePixelRatio, devicePixelRatio);

// 2) 切换后台标签页时暂停（节省 CPU / 电池）
document.addEventListener('visibilitychange', () => {
  if (document.hidden) cancelAnimationFrame(raf);
  else raf = requestAnimationFrame(tick);
});

// 3) 整体 try/catch：任何异常直接放弃粒子层，不影响页面
try { initParticles(); } catch (e) { /* 静默降级 */ }
规范要求：粒子数量 30-80；颜色使用蓝色系（rgba(0-90, 122-200, 255, 0.2-0.4)）；移动端可降级为静态噪点或直接关闭；必须在 prefers-reduced-motion 下整体禁用；Canvas 尺寸按 devicePixelRatio 缩放。

2.2 Liquid Glass 层次

借鉴 Apple Liquid Glass 语言：卡片由「背景模糊玻璃层 + 半透明主体层 + 顶部高光描边 + 柔和投影」构成。本站采用真实折射管线：backdrop-filter 引用 SVG feTurbulence / feDisplacementMap 滤镜，让玻璃边缘产生透镜弯曲与色散。

实现原理（三层管线）：

  • blur(1px)：保证浏览器把该元素视为「背景模糊目标」，强制管线执行；
  • url(#lg-refract)：SVG feDisplacementMap 按 feTurbulence 噪声位移背后像素，产生真实透镜弯曲；
  • saturate/brightness/contrast：折射后增强色彩鲜活度、模拟透镜聚光、锐化边缘。

背景前提：折射的可视前提是背后有「可弯曲的高频内容」（条纹、光斑、文字），纯色背景折射不可见。这就是官网背景使用高频网格条纹的原因。

Liquid Glass 卡片核心样式（真折射）css
.lg-glass {
  background: rgba(255,255,255,0.72);
  border: 1px solid #c8def8;
  border-radius: 20px;
  backdrop-filter: blur(1px) url(#lg-refract)
                   saturate(280%) brightness(1.10) contrast(1.06);
  -webkit-backdrop-filter: blur(1px) url(#lg-refract)
                   saturate(280%) brightness(1.10) contrast(1.06);
  box-shadow: 0 1px 3px rgba(0,50,120,0.03),
              0 4px 16px rgba(0,50,120,0.02);
}
三档折射滤镜（标准 / 强 / 弱）svg
<!-- 标准：常态玻璃 -->
<filter id="lg-refract" x="-20%" y="-20%" width="140%" height="140%">
  <feTurbulence type="fractalNoise" baseFrequency="0.008 0.012"
                numOctaves="4" seed="5" result="noise"/>
  <feDisplacementMap in="SourceGraphic" in2="noise" scale="50"
                     xChannelSelector="R" yChannelSelector="G" result="displaced"/>
  <feComposite in="displaced" in2="SourceGraphic" operator="in"/>
</filter>
<!-- 强折射（hover 玻璃变厚）：低频大位移 -->
<filter id="lg-refract-strong">
  <feTurbulence baseFrequency="0.004 0.006" numOctaves="4" seed="7" result="noise"/>
  <feDisplacementMap in2="noise" scale="80" result="displaced"/>
</filter>
<!-- 弱折射（active 玻璃变薄）：高频小位移 -->
<filter id="lg-refract-weak">
  <feTurbulence baseFrequency="0.03 0.04" numOctaves="2" seed="2" result="noise"/>
  <feDisplacementMap in2="noise" scale="12" result="displaced"/>
</filter>
规范要求：层次感依靠「透明度 + 模糊 + 折射 + 描边」而非浓重实色；同一层级玻璃参数全局统一；blur 值必须 ≥1px（0 会被浏览器忽略整条声明）；禁用纯 #fff 不透明背景与 CSS 假高光（inset 白光、径向高光层），否则玻璃感变成保鲜膜/塑料。降级判断使用 @supports not (backdrop-filter: url(#test))，不支持 SVG 滤镜时退回纯 blur()，否则折射效果丢失。

2.3 高斯背景玻璃模糊

内容层背后的元素经高斯模糊形成真实磨砂玻璃效果。原生 backdrop-filter 性能远优于截图模糊方案，滚动与交互均更流畅。

层级模糊半径饱和度亮度典型用途

玻璃卡片12-16px180-200%1.05-1.10content-card、feature-card
折射玻璃1-3px280-350%1.10-1.18配合 SVG 滤镜的真折射元素

.glass-nav {
  position: fixed; top: 0; left: 0; right: 0;
  background: rgba(255,255,255,0.82);
  backdrop-filter: blur(20px) saturate(180%) brightness(1.05);

}
完整降级矩阵（三档能力检测）css
/* ① 不支持 backdrop-filter：保留半透明底色与边框即可读 */
@supports not ((backdrop-filter: blur(1px)) or (-webkit-backdrop-filter: blur(1px))) {
  .glass-nav { background: rgba(255,255,255,0.92); }
}

/* ② 支持 blur 但不支持 SVG 折射：退回纯强模糊 */
@supports not (backdrop-filter: url(#test)) {
  .lg-glass {
    backdrop-filter: blur(20px) saturate(180%) brightness(1.05) !important;
    -webkit-backdrop-filter: blur(20px) saturate(180%) brightness(1.05) !important;
  }
}
规范要求：模糊半径 16-28px 观感最佳；避免大面积模糊造成 GPU 压力；滚动容器使用 transform 位移而非 top 触发重排；大面积玻璃层数量控制在 3-4 个以内，超出部分用预模糊纹理替代。

2.4 自然位置变化

元素位置变化必须「物理自然」：接近-上浮-回落的过程带惯性与回弹，而非生硬瞬时位移。使用缓动曲线让运动拥有重量感。

缓动曲线用途特征
cubic-bezier(.22, 1, .36, 1)上浮、展开、常规进入快出缓停，成熟稳重
cubic-bezier(.22, 1.4, .36, 1)按钮 hover 上浮带回弹，活泼但不跳脱
cubic-bezier(.16, 1, .3, 1)弹层出现、模态干脆利落的强调进入
cubic-bezier(.25, .8, .35, 1)颜色 / 阴影过渡通用液态过渡
自然上浮 hover（带回弹）css
.float-item {
  transition: transform .3s cubic-bezier(.22, 1, .36, 1);  /* 成熟缓动 */
}
.float-item:hover { transform: translateY(-3px); }
.float-item:active { transform: translateY(-1px) scale(0.985); }  /* 按压压缩 */
规范要求：位移幅度 3-6px；时长 0.25-0.35s；统一使用同一缓动曲线族，保证整体节奏一致；对 prefers-reduced-motion 用户应关闭位移；按压态（active）用 scale(0.98-0.99) 模拟液态压缩，时长缩至 0.08-0.1s。

const btn = document.querySelector('.hw-btn');
btn.addEventListener('pointermove', (e) => {
  const r = btn.getBoundingClientRect();
  const x = ((e.clientX - r.left) / r.width) * 100;
  const y = ((e.clientY - r.top) / r.height) * 100;

04

跟随手势 / 鼠标 / 头部摆动的动态光影

DYNAMIC LIGHT

让光源跟随用户的鼠标、手指或设备朝向移动，光影随之「活」起来。桌面端优先 mousemove；移动端可使用触摸滑动与设备方向（陀螺仪）；头部摆动主要服务于移动端 AR / 陀螺仪场景，桌面端可用鼠标模拟。设计目标是「有生命感、但不打扰」：反馈幅度克制、更新频率合并、无权限时优雅降级。

4.1 跟随鼠标（桌面端）

卡片随鼠标产生轻微 3D 倾斜，同时一个光斑跟随光标移动。这是空间光感中最具「高级感」的交互，也是商城卡片的标准反馈。倾斜让卡片获得「厚度」，光斑让表面获得「光照」，二者叠加即物理化的光场反馈。

移动鼠标
观察倾斜与光斑
参数推荐值说明
透视距离600px越小倾斜越夸张，过小会产生强烈畸变
rotateX 幅度≤ 8deg前后倾斜上限，超过会明显「塌陷」
rotateY 幅度≤ 10deg左右倾斜上限，保持克制的高级感
光斑尺寸120-160% 卡片尺寸用 inset: -2px 的覆盖层实现，避免裁剪
光斑透明度0.35-0.45过亮会盖住内容文字
退出过渡transform .3smouseleave 时平滑复位，禁止瞬跳
鼠标跟随 + 光斑实现（RAF 合并版）javascript
const card = document.getElementById('spotCard');
const spot = document.getElementById('spotLight');
let raf = 0;
card.addEventListener('mousemove', (e) => {
  const r = card.getBoundingClientRect();
  const x = (e.clientX - r.left) / r.width;
  const y = (e.clientY - r.top) / r.height;
  // 1) 把坐标写入 CSS 变量（光斑定位用）
  card.style.setProperty('--mx', (x*100).toFixed(1) + '%');
  card.style.setProperty('--my', (y*100).toFixed(1) + '%');
  // 2) 每帧只提交一次 transform / 光斑位置（性能关键）
  cancelAnimationFrame(raf);
  raf = requestAnimationFrame(() => {
    card.style.transform =
      `perspective(600px) rotateX(${(0.5-y)*8}deg) rotateY(${(x-0.5)*10}deg)`;
    spot.style.left = `${x*100}%`;
    spot.style.top  = `${y*100}%`;
  });
});
card.addEventListener('mouseleave', () => {
  cancelAnimationFrame(raf);
  card.style.transform = '';
  // 3) 光斑同时复位，避免光标移出后残留亮点
  spot.style.opacity = 0;
});
card.addEventListener('mouseenter', () => { spot.style.opacity = 1; });
规范要求：倾斜角度不超过 8-10deg；必须合并进 requestAnimationFrame 批量更新，避免性能抖动；getBoundingClientRect 只在事件回调中读取、不进 RAF 内部重复调用；mousemove 监听在 touch 设备上无副作用，但仍建议用 pointermove 统一入口；悬停卡片数量超过 6 个时，只保留首屏 2-3 个卡片启用倾斜，其余用光斑。

4.2 跟随手势 / 头部摆动（移动端）

移动端通过陀螺仪感知设备朝向，光斑位置随设备倾斜与头部摆动而变化；触摸滑动可驱动内容层视差。实现均需处理权限与降级。头部摆动本质上就是 deviceorientation 的 beta/gamma 组合，无需额外传感器。

事件 / API适用场景注意点
deviceorientation陀螺仪驱动光斑 / 视差iOS 13+ 需 requestPermission，需 HTTPS
touchmove / pointermove触摸滑动驱动视差合并进 RAF，避免滚动冲突用 passive:true
Devicemotion加速度计驱动惯性低频采样，避免误触发
设备方向（陀螺仪）驱动光斑javascript
window.addEventListener('deviceorientation', (e) => {
  const g = e.gamma || 0;   // 左右倾斜 -90 ~ 90
  const b = e.beta  || 0;   // 前后倾斜 -180 ~ 180
  spot.style.left = `${50 + g * 0.5}%`;
  spot.style.top  = `${50 - b * 0.4}%`;
});
/* iOS 13+ 需要请求权限（必须在用户手势回调里调用） */
if (typeof DeviceOrientationEvent !== 'undefined'
    && typeof DeviceOrientationEvent.requestPermission === 'function') {
  document.querySelector('.hw-btn').addEventListener('click', () => {
    DeviceOrientationEvent.requestPermission().then(state => {
      if (state === 'granted') { /* 已授权，监听生效 */ }
    }).catch(() => { /* 拒绝：走降级 */ });
  });
}
/* 降级开关：无陀螺仪或未授权时，退回静态光斑 */
if (!('DeviceOrientationEvent' in window)) {
  spot.style.background = 'radial-gradient(circle at 50% 50%, rgba(255,255,255,0.35), transparent 70%)';
}
重要降级：用户拒绝权限、桌面浏览器或低端设备不支持陀螺仪时，必须自动回退为「静态光斑 / 鼠标跟随 / 关闭」三档之一，严禁让光影区域出现空白交互；iOS 的 requestPermission 必须在用户点击回调中调用，否则返回 denied；必须在 prefers-reduced-motion 下跳过全部动态光影。

4.3 性能与降级矩阵

动态光影是「可牺牲」的增强层：它的优先级永远低于内容可读性与交互可用性。接入任何动态效果前，先规划好三层能力检测。

能力检测方式支持降级动作
Pointer Events'PointerEvent' in window现代浏览器回退 mousemove + touchmove 双监听
requestAnimationFrame'requestAnimationFrame' in window全平台setTimeout(16ms) 模拟
deviceorientation'DeviceOrientationEvent' in window移动端为主静态光斑 / 关闭
prefers-reduced-motionmatchMedia('(prefers-reduced-motion: reduce)')系统级偏好禁用倾斜、流光、粒子、视差
低电量模式navigator.getBattery（部分浏览器）Chrome / Edge降低粒子数量或关闭
统一降级入口javascript
const reduce = window.matchMedia('(prefers-reduced-motion: reduce)');
const okPointer = 'PointerEvent' in window;
if (reduce.matches) { /* 全部动态效果关闭 */ }
else if (okPointer)   { /* pointermove 驱动光斑 + 倾斜 */ }
else                  { /* mousemove + touchmove 双监听 */ }
规范要求：动态光影的 JS 必须整体 try/catch 包裹，任何异常只影响效果层、不影响页面功能；效果层不得阻塞主线程超过 2ms/帧（用 Performance 面板观察 Long Task）；移动端优先考虑续航，粒子与光斑同时存在时总量减半。

响应式与全设备适配

RESPONSIVE

商城用户覆盖桌面（Windows / macOS / Linux）与移动端（iOS / Android），上架页面必须全局适配所有浏览器。以下为断点、安全区、触控与兼容性要求。核心原则是「移动优先设计、桌面渐进增强」：先保证窄屏内容完整可读，再叠加宽屏布局与视觉效果。
